## Images and Headless

`@deepseek-ai/dsh-tool-fs` supplies `read_image({ file_path })`. It reads through the existing `ctx.fs`, accepts PNG/JPEG/WebP/GIF and recognized extensionless images, and commits its result through `ctx.attachments`. Registration requires an attachment service; execution requires the exact model route to declare image input. The shipped `deepseek-flash` model does so. Existing Headless still takes text or stdin and a Session ID; pointing the task to staged local files reuses its normal tool loop. Sources: [official image tool](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/fs/tool-fs/src/read-image.ts), [model catalog](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/src/models.ts), [Headless](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/bundle/headless/README.md).

The local attachment provider admits sources up to 20 MiB, 64 million pixels and 8192 pixels per side; a message allows 20 images and 200 MiB. Its installed implementation normalizes to a 4,194,304-pixel budget, an 8192-pixel long-edge cap and a 4 MiB encoding target. Normalization can resize, strip metadata and re-encode; animated input becomes a single frame. Stored normalized bytes are distinct from the original repository file. Source: [official local provider and constants](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment-local/src/index.ts), [normalization](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment-local/src/normalization.ts). The source and installed package take precedence over the older normalization defaults still printed in the subsystem narrative.

## Attachment and Files APIs

The public `AttachmentStore` owns `saveImage`, `readImage`, `imageHostPath`, `saveFile`, `saveFileStream`, `readFileStream` and `fileHostPath`. Image references carry opaque IDs and verified media/size/dimensions; file references carry the opaque ID, exact size and sanitized name. Generic files are stored verbatim. The Action must ask the provider for object locations rather than derive paths from IDs. Sources: [public storage seam](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment/src/index.ts), [reference types](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment/src/types.ts).

`dsh-llm-deepseek` already owns request-image preparation, Files API upload/reuse/expiry and bounded inline fallback. Its public `DeepSeekFilesClient.upload` accepts image media types. The existence of this Files API does not establish PDF or Office understanding. The Action should let the official adapter perform its image transport and keep credentials in its existing proxy boundary. Source: [official Files transport](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/src/files-api.ts), [adapter contract](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/README.md).

## SDK, ACP and Session persistence

The SDK protocol accepts inline raster blocks with canonical base64 data and a PNG/JPEG/WebP/GIF MIME type. ACP also admits inline images into the durable attachment service. Their resume operations open already persisted Sessions; switching the Action from Headless is unnecessary. Sources: [SDK protocol](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/sdk/protocol/src/types.ts), [ACP image admission](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/acp/acp/src/content.ts).

`dsh-session-log-export` publicly exposes `sessionLogZipEntries` and `streamSessionLogZip`, exporting canonical logs and referenced images/files. It has no archive-import API. Lower-level public APIs suffice for the existing Action checkpoint. The Controller obtains image paths through `imageHostPath` and verifies byte identity with `commitPreparedImageFile`, which checks the opaque ID against the digest and byte count. Import uses that same public publisher to retain the original reference. Full media and dimension validation remains in the official Worker attachment reader when the restored image is used; the Controller does not load a native image decoder. For generic files, `readFileStream` and `saveFileStream` preserve bytes and return the same reference. The Action keeps the existing raw V4 Session log and adds only attachment byte entries to its existing GitHub artifact envelope. Sources: [official export](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session-query/session-log-export/src/archive.ts), [public normalized-image commit and verified read](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment-local/src/store.ts), [verbatim file storage](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/attachment/attachment-local/src/file-store.ts).

Local integration tests exercise all four raster formats, normalization metadata, binary and empty generic files, separate source/destination homes, ZIP transport, exact raw-log preservation and refusal of missing, modified or inconsistent objects. These checks establish storage and restore behavior; live Actions runs and model interpretation require their own release evidence.

## PDF, Word and Excel

`dsh-skill-office` provides instructions for DOCX/PPTX/XLSX authoring and Office rendering/recalculation/PDF export. Those workflows depend on separately configured Python libraries, Node and LibreOffice Kit, and execute through the existing approved shell. It is not a standalone PDF/Office parser callable through Headless. This release can carry file bytes without claiming arbitrary-format understanding. An operator can explicitly configure official skills, tools and their dependencies through existing extension controls; opening a document must not implicitly grant shell or network permissions. Source: [official Office skill provider](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/skill/skill-office/README.md).
